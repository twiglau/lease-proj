## JDK 配置冲突诊断与修复（Maven Toolchains）

**现象**：IDEA 提示"项目 JDK 配置不正确"，用户要求先只列步骤不改；后反馈"还是不对"，要求主动修复并给出问题点。

**真正根因（用真实构建复现锁定）**：
- `~/.zshrc` 第 9-14 行为另一个项目 public_chain（Spring Boot 2.2.6）把全局 JAVA_HOME **写死 Java 8**：`export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-1.8.jdk/Contents/Home`
- lease-proj 要求 Java 17，命令行 `mvn clean compile` 直接报 `Fatal error compiling: 无效的目标发行版: 17`
- IDEA 侧其实已配对：`MavenRunner.jreName=openjdk-17`（workspace.xml 第47行）、根 `.idea/misc.xml` 的 `project-jdk-name=openjdk-17` 都正确

**关键约束**：不能直接改全局 JAVA_HOME 为 17——会破坏依赖 Java 8 的 public_chain。用户偏好项目级工具链、不污染全局环境。

**修复方案（项目级隔离，不动全局 JAVA_HOME）**：
1. 新增 `~/.m2/toolchains.xml`：注册 JDK 17（`/Users/feiya/Library/Java/JavaVirtualMachines/openjdk-17.0.2`）和 JDK 1.8 两个 toolchain。此文件只登记不改默认，不影响其他项目。
2. 根 `pom.xml` 的 `<build><plugins>` 加 `maven-toolchains-plugin:3.1.0`，配置 `<jdk><version>17</version><vendor>oracle</vendor></jdk>`，绑定 toolchain goal（默认 validate 阶段）。

**验证**（保持 JAVA_HOME=8 启动 Maven）：日志出现 `Toolchain in maven-compiler-plugin: JDK[.../openjdk-17.0.2]`、`Toolchain in maven-surefire-plugin: JDK[...]`，`Tests run: 1, Failures: 0, Errors: 0`，**BUILD SUCCESS**。两个项目互不干扰。

**经验**：多项目 JDK 版本冲突时，Maven Toolchains 是标准解法——全局 JAVA_HOME 保持某个项目所需版本，需要不同 JDK 的项目用 toolchains 在 pom 里声明，编译/测试插件自动切换。比改全局环境变量或写启动脚本更干净。

**排查中已澄清的非问题项**：
- hello-mp/.idea 目录已被删（之前残留的 `openjdk-17 (2)` 无效 JDK 名已消失）
- hello-mp/pom.xml 被手动加回 lombok 依赖（无害，Spring Boot parent 管理版本）

## IDEA 编辑器报「无法解析符号 String/Long/Integer」修复（jdk.table.xml roots 丢失）

**现象**：User.java 里 `Long`/`String`/`Integer`（java.lang 基础类）全部标红，命令行 `mvn clean test` 却 BUILD SUCCESS。

**根因**：IDEA 全局 JDK 表 `~/Library/Application Support/JetBrains/IntelliJIdea2026.1/options/jdk.table.xml` 里 `openjdk-17` 条目的 `<classPath>` 是空的——`<root type="composite" />`，classPath roots 数 = 0（对比：正常的 JDK 27 有 65 个 jrt 模块 root）。IDEA 靠这些 jrt:// 模块路径提供 java.lang.*，roots 为空 → 基础类全部无法解析。命令行直接读 JDK 目录，不受影响。

**修复**：用 `java --list-modules` 拿到 JDK17 实际的 70 个模块，按 JDK27 的 `jrt://<home>!/<module>` 格式写进 openjdk-17 的 classPath，sourcePath 补 `jar://<home>/lib/src.zip!/`。备份 jdk.table.xml.bak-20261119，XML 校验通过，roots=70 含 java.base。

**关键注意**：IDEA 正在运行时改 jdk.table.xml，内存旧状态可能在退出时回写覆盖。让用户**强制退出**（⌘⌥Esc 强退）再重开，或重启后到 Project Structure 确认 SDK。若被覆盖，用 UI 方案：Project Structure → SDKs → 删 openjdk-17 → 重新 Add JDK 指向该路径，IDEA 会自动重建 roots。

**经验**：IDEA 里 java.lang 基础类标红 = JDK 的 classPath roots 丢失（不是代码/依赖问题）；命令行能编译是重要判别信号。JDK 9+  root 格式是 `jrt://<JDK home>!/<module>`。
