## hello-mp 项目 pom.xml 修复（Spring Boot 3.0.11）

**背景**：用户问 start.spring.io 没有 3.0.12 怎么办。实测该站现只提供 4.x（默认 4.1.2；4.0.9 稳定；其余 RC/SNAPSHOT），3.x 全下架；3.0.11 在 Maven Central 仍可下载（200）。用户选择了 3.0.11。

**环境更正**：本机其实有 JDK 17.0.2（`/Users/feiya/Library/Java/JavaVirtualMachines/openjdk-17.0.2`），IDEA 也自带 JBR；之前只看 java_home -V 漏判说"只有 Java 8"是错的。Maven 3.9.16 默认挂在 Java 8，需显式设 JAVA_HOME 到 17。

**根因**：pom.xml 里 parent 版本 3.0.11 是对的，但被误把 `modelVersion`/`xmlns`/`schemaLocation` 全改成 3.0.0（误以为对应 Spring Boot 3.x）。modelVersion 是 POM 模型版本，恒为 4.0.0。另有一个多余的 maven-compiler-plugin 配了无版本的 lombok annotationProcessorPath，源码根本没用 Lombok。

**修复**：
1. modelVersion/xmlns/schemaLocation 三处 3.0.0 → 4.0.0
2. 删除无版本的 lombok 依赖 + 整段 maven-compiler-plugin（parent 已管理版本）
3. 清理 IDEA 自动生成的空占位标签（url/licenses/developers/scm）

**验证**：用 JDK 17 跑 `mvn clean test` → BUILD SUCCESS，Tests run: 1, Failures: 0, Errors: 0，日志显示 Spring Boot v3.0.11 on Java 17.0.2。

## MyBatis-Plus 版本验证（3.5.3.2 vs Boot3 starter）

- 用户问 MP 3.5.3.2 配置是否正确。最初凭 POM 里 `spring-boot-dependencies:2.5.3` 判断不兼容，实测推翻：3.5.3.2 的 jar 同时带 spring.factories 和 AutoConfiguration.imports，Boot 3 能识别，Mapper CRUD 实测通过。

- 另注意：hello-mp 的 @SpringBootTest 若未配数据源会报 "Failed to determine a suitable driver class"（与 MP 版本无关）；本次改造后 test 通过的原因待观察。
